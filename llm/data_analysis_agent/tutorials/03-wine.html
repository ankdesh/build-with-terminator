01

Load the data and its meaning

Start the builder once from the repository root. Keep this guide in another browser tab. Use New project → Data → Upload CSV and select the downloaded file. Do not upload a second dataset into this project.

Reuse the running builder. Select New project so this lesson has separate stages, controls and data. Rename it from the project name in the top bar.

Paste this into Data → Business context, then leave the field to save.

Business context
Each row is a measured red or white Vinho Verde wine sample from the UCI source. wine_type identifies the source file. Quality is an ordered sensory score from 0 to 10, not a percentage. Alcohol is percent by volume. Repeated measurements may be distinct samples: preserve all rows. Comparisons and correlations are descriptive; they do not establish cause or support health claims.
02

Create stages, then Run

Open Chat on the right, paste the complete prompt, and send it. Keep Project chat context for these whole-dashboard prompts. Clear any selected stage first. Chat prepares changes; review the affected stages and select Apply. It does not run calculations.

Prompt 1
Build a desktop dashboard with separate Data cleaning and Analysis stages and the requested Visualization widgets. Give widgets the exact titles listed below so I can check them. Use readable English labels and correct units. Keep the original CSV unchanged. Preserve repeated observations unless I explicitly ask otherwise. Use standard column bindings for ordinary bar, pie, line and scatter charts so I can edit their bindings in Properties. For advanced charts return JSON-only ECharts options from the analysis. Use no external chart resources or JavaScript callbacks. Declare parameters_used for each step. Add a full table export where requested; do not truncate the underlying table. Save the stages; I will select Run.
Cleanup must preserve every row and every source measurement, including repeated rows. Add a wine_type select filter on cleaned data with All (null), and quality_threshold integer default 7, minimum 0, maximum 10. The threshold is a scenario parameter, not a row-removing filter.
Metrics: 'Samples' (row count), 'Mean quality' (mean quality, three decimals), 'At or above threshold' (count quality >= quality_threshold).
Create 'Alcohol distribution' as a histogram using fixed edges 8.0, 8.5, ..., 15.0 percent alcohol. Bins are left-inclusive/right-exclusive except the last includes its right edge. Show count on Y and alcohol ranges on X.
Create 'Alcohol by wine type' as a native ECharts boxplot of alcohol grouped by wine_type. Use minimum, 25th percentile, median, 75th percentile and maximum, with linear quantile interpolation. Label that the whiskers are min/max, not Tukey outliers. Do not silently drop rows.
Create full table 'Quality summary' with wine_type, sample_count, mean_quality, median_alcohol and count_at_threshold for the current selection.
Use exactly one cleanup stage returning cleaned and one initial analysis stage returning these six separately declared outputs: samples (scalar count), mean_quality (scalar), threshold_count (scalar), alcohol_distribution (DataFrame with bin_label and count columns), alcohol_by_type (dictionary with an option key containing native ECharts boxplot options), quality_summary (DataFrame). Bind the three metric widgets to the three separate scalar outputs; never bind a metric to a dictionary of metrics. Use numpy.histogram with bins=np.arange(8.0,15.5,0.5) for the stated bin semantics. The boxplot widget must have chart_binding=null, and its ECharts series data must contain one five-number array per wine type, not a pandas describe table. Keep all table column names unique strings.
For the boxplot use this exact structure with computed data: groups=sorted(df['wine_type'].unique().tolist()); five_numbers=[np.quantile(df.loc[df['wine_type']==group,'alcohol'],[0,.25,.5,.75,1]).tolist() for group in groups]; alcohol_by_type={'option':{'xAxis':{'type':'category','data':groups},'yAxis':{'type':'value','name':'Alcohol (% ABV)'},'series':[{'type':'boxplot','data':five_numbers}]}}. Do not return describe().to_dict(), which is a statistics dictionary rather than an ECharts chart.

Open Pipeline. Expect Data input, Data cleaning, Analysis, and Visualization cards. Inspect the cleaning purpose and its input/output links. Then select Run. Wait for the successful run state before comparing values. In Data → Input contract, review the column types and descriptions. Keep numeric measurements numeric and identifiers as text; an input-contract change needs Run.

Extend the analysis through chat

Return to Chat, clear stage context to Project, and send the next prompt. Review and Apply the proposal to add the next view. Then select Run.

Prompt 2
Add a native ECharts heatmap titled 'Measurement correlations' using the current filtered samples. Use Spearman correlations, with rows and columns in this order: alcohol, density, residual sugar, volatile acidity, sulphates, quality. Show a diverging colour scale fixed from -1 to +1 with zero in the centre. Include all 36 cells and label the axes. Compute labels=['alcohol','density','residual sugar','volatile acidity','sulphates','quality']; matrix=df[labels].corr(method='spearman'); cells=[[x,y,float(matrix.iloc[y,x])] for y in range(6) for x in range(6)]. Return {'option':{'xAxis':{'type':'category','data':labels},'yAxis':{'type':'category','data':labels},'visualMap':{'min':-1,'max':1,'inRange':{'color':['#245bd7','#ffffff','#bd3945']}},'series':[{'type':'heatmap','data':cells}]}} as the chart artifact and set chart_binding=null. Do not flatten the matrix to bare numbers: each cell needs its x index, y index and value. Python booleans are True/False. Add computed text 'Correlation notes' explaining that quality is ordinal, that Spearman measures ranked association, and that correlation does not establish cause. Preserve all existing calculations and controls. I will select Run.

05

Edit, inspect and undo

In Dashboard, drag a widget handle, resize its lower-right corner, or use Alt + arrow keys on a selected widget. Properties also offers Column, Row, Width and Height. The grid always has 12 columns; narrow desktop windows scroll rather than become a phone layout.

Use Dashboard settings for title/subtitle, and Filters and scenario defaults for labels, defaults and ranges. Change a title or number format and check the live target without Run. Changed calculation defaults remain pending until Run.

  • Select the analysis card that uses quality_threshold. Properties should show only controls declared by that stage, not every dashboard field.
  • Change quality_threshold to 6 in the target and Apply. Samples and Mean quality remain unchanged; the threshold count increases or stays equal.
  • Select a heatmap or box-plot card. These advanced options are produced by analysis; their structure is changed through chat rather than the standard binding dropdown.
  • Read the chart tooltip, compare red and white using the filter, then Reset and Apply to return to the reference defaults.

Use Undo and Redo in the workspace toolbar for committed development edits. Target-side temporary controls do not become development edits.

07

Export results and accept a revision

From a chart, download PNG. From a table, download CSV and check the complete row count. In the builder, Run the default workspace, review cleanup effects, then select Accept revision. Confirm the cleanup review when requested. History keeps accepted revisions while you continue editing.

Windows prerequisite: Download needs the compatible Windows runtime archive configured by the project maintainer. This pack verifies acceptance and the explicit missing-runtime error; it does not include a Windows executable or claim a real Windows smoke test. A missing runtime archive must not produce a fake application ZIP.
