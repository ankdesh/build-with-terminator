Know the input

Real observations. Clear definitions.

Column dictionary and preparation

Convert Excel to CSV; retain all rows from 2011-01-01 inclusive to 2011-04-01 exclusive in source order. Normalize dates to ISO and identifiers to text. No analytical cleaning.

ColumnMeaning and units
InvoiceNoInvoice identifier; a C prefix marks cancellation. Read as text.
StockCodeItem identifier; includes non-product charge codes. Read as text.
DescriptionSource item description; may be missing.
QuantityUnits on this invoice line; negative values can represent returns.
InvoiceDateSource invoice date and time, normalized to ISO text; no timezone is supplied.
UnitPricePrice per unit in pounds sterling (GBP).
CustomerIDCustomer identifier as text; missing IDs must not remove valid sales.
CountryCustomer country. Results are historical, not current market figures.

Source: Online Retail · Q1 2011 · CC-BY-4.0. Retrieved 2026-11-04. See attribution and hashes and transformations.

  • The supplied CSV includes every source row in the quarter; it is not a random sample. The workbook-to-CSV conversion is recorded in the manifest.
  • Excluded cancellations and non-positive lines are reported, not silently treated as completed sales. Missing customers remain in the totals.
  • The discount result is arithmetic under fixed quantities. It is not a demand forecast, profit estimate, or current market claim.
01

Load the data and its meaning

Start the builder once from the repository root. Keep this guide in another browser tab. Use New project → Data → Upload CSV and select the downloaded file. Do not upload a second dataset into this project.

Reuse the running builder. Select New project so this lesson has separate stages, controls and data. Rename it from the project name in the top bar.

Paste this into Data → Business context, then leave the field to save.

Business context
This is a historical UK retailer extract for January–March 2011. UnitPrice is GBP per unit. A C prefix in InvoiceNo marks cancellation. Positive invoice-line sales value is Quantity × UnitPrice on non-cancelled lines with Quantity > 0 and UnitPrice > 0. This is not profit or refund-adjusted net revenue. Missing CustomerID must not remove valid sales. Keep potential duplicate lines because the source has no invoice-line identifier.
02

Create stages, then Run

Open Chat on the right, paste the complete prompt, and send it. Chat creates and saves stages; it does not run calculations.

Prompt 1
Build a desktop dashboard with separate Data cleaning and Analysis stages and the requested Visualization widgets. Give widgets the exact titles listed below so I can check them. Use readable English labels and correct units. Keep the original CSV unchanged. Preserve repeated observations unless I explicitly ask otherwise. Use standard column bindings for ordinary bar, pie, line and scatter charts so I can edit their bindings in Properties. For advanced charts return JSON-only ECharts options from the analysis. Use no external chart resources or JavaScript callbacks. Declare parameters_used for each step. Add a full table export where requested; do not truncate the underlying table. Save the stages; I will select Run.
Read InvoiceNo, StockCode and CustomerID as nullable text and InvoiceDate as datetime. Cleanup must keep all source rows, normalize dates, fill missing Description and CustomerID with 'Unknown', and add is_valid_sale for non-cancelled InvoiceNo (case-insensitive C prefix), Quantity > 0 and UnitPrice > 0. Do not deduplicate.
Add a Country select filter on cleaned data with All (null), and a numeric discount_pct scenario default 0, minimum 0, maximum 30. Discount only scales sales value; it does not predict a change in quantity. Put the Country control in the root parameters array: {"id":"country","label":"Country","kind":"select","default":null,"minimum":null,"maximum":null,"choices":[],"filter_column":"Country","filter_artifact":"cleaned","filter_operator":"eq"}. It is not a visualization widget.
Analysis uses only valid sale rows for sales metrics and charts, while 'Excluded lines' counts invalid lines in the currently filtered data. Metrics: 'Sales value' (sum Quantity × UnitPrice, GBP, two decimals), 'Invoice lines' (valid line count), 'Invoices' (distinct valid InvoiceNo count), 'Excluded lines', 'Scenario sales value' (Sales value × (1 - discount_pct/100)).
Charts: 'Sales by country' (top ten countries ranked by sales value, bar), 'Daily sales' (sum by observed calendar date, line), and 'Top invoice items' (top ten Description values ranked by sales value, horizontal bar). Labels must not claim that all item codes represent physical products.
Create full table 'Invoice detail' with every valid invoice line, original columns and sales_value. Never use head() for its exported result. Do not add a pie chart with dozens of countries.
Keep the graph small: one cleanup step returns cleaned; one analysis step takes cleaned and returns all nine named outputs: sales_value, invoice_lines, invoices, excluded_lines, scenario_sales_value, country_totals, daily_sales, top_items, invoice_detail. Declare these exact names in that analysis step's outputs list and return each of them from its function. First assign valid_sales=valid_sales.assign(sales_value=valid_sales.Quantity*valid_sales.UnitPrice). Compute country_totals=valid_sales.groupby('Country',as_index=False)['sales_value'].sum().nlargest(10,'sales_value'); compute daily_sales=valid_sales.assign(date=valid_sales.InvoiceDate.dt.strftime('%Y-%m-%d')).groupby('date',as_index=False)['sales_value'].sum(). Never aggregate Quantity and label it sales value. country_totals is a DataFrame with Country and sales_value, daily_sales a DataFrame with date and sales_value; bind the country bar and daily line directly to those DataFrames. Build item_totals=valid_sales.assign(sales_value=valid_sales.Quantity*valid_sales.UnitPrice).groupby('Description',as_index=False)['sales_value'].sum().nlargest(10,'sales_value'); top_items={'option':{'xAxis':{'type':'value','name':'GBP'},'yAxis':{'type':'category','data':item_totals.Description.tolist()},'series':[{'type':'bar','data':item_totals.sales_value.tolist()}]}}. Its widget chart_binding must be null. invoice_detail is the full valid-line DataFrame. Metric widgets bind the five separate scalar outputs, not a metrics dictionary. Do not create chart widgets that refer to undeclared or differently named outputs.

Open Pipeline. Expect Data input, Data cleaning, Analysis, and Visualization cards. Inspect the cleaning purpose and its input/output links. Then select Run. Wait for the successful run state before comparing values. In Data → Input contract, review the column types and descriptions. Keep numeric measurements numeric and identifiers as text; an input-contract change needs Run.

05

Edit, inspect and undo

In Dashboard, drag a widget handle, resize its lower-right corner, or use Alt + arrow keys on a selected widget. Properties also offers Column, Row, Width and Height. The grid always has 12 columns; narrow desktop windows scroll rather than become a phone layout.

Use Dashboard settings for title/subtitle, and Filters and scenario defaults for labels, defaults and ranges. Change a title or number format and check the live target without Run. Changed calculation defaults remain pending until Run.

  • Select Daily sales and switch its standard binding from line to bar, then Undo.
  • In the target, change discount_pct to 10 and select Apply controls. Sales value stays the same; Scenario sales value becomes 90% of it.
  • Edit a dashboard title in Dashboard settings and watch the target update without Run. Change a calculation default, observe Changes pending, then select Run.
  • Download Invoice detail CSV. Compare its complete row count with Invoice lines; the on-screen preview may show fewer rows.

Use Undo and Redo in the workspace toolbar for committed development edits. Target-side temporary controls do not become development edits.

07

Export results and accept a revision

From a chart, download PNG. From a table, download CSV and check the complete row count. In the builder, Run the default workspace, review cleanup effects, then select Accept revision. Confirm the cleanup review when requested. History keeps accepted revisions while you continue editing.

Windows prerequisite: Download needs the compatible Windows runtime archive configured by the project maintainer. This pack verifies acceptance and the explicit missing-runtime error; it does not include a Windows executable or claim a real Windows smoke test. A missing runtime archive must not produce a fake application ZIP.
